## 1. Bối cảnh

Ba ticket trước tạo ra 3 hạ tầng test rời. Không gộp thì mỗi người phải nhớ 3
lệnh và thứ tự chạy — thực tế sẽ có người quên, rồi commit làm đỏ tầng khác.

Đây cũng là ticket **chốt tài liệu ranh giới BE/FE** mà chủ dự án yêu cầu minh bạch.

## 2. Phạm vi

**Trong:** script `package.json` · cổng CI · file hợp đồng API · tài liệu ranh giới.

**Ngoài:** viết thêm test case mới.

## 3. Dữ liệu vào / ra

```
apps/2026-thenamduhill/package.json    thêm test:sql · test:api · test:unit · test · test:all
packages/core/src/api-contracts.ts     MỚI — hợp đồng API. BE sở hữu, FE chỉ đọc
handover/tasks/relelase-v1.0.1/TEST-STRATEGY.md   cập nhật số liệu THẬT đo được
```

## 5. Tiêu chí chấp nhận (AC)

| # | AC | Kiểm bằng |
|:--:|---|---|
| 1 | `pnpm test` chạy **tầng 1+2+3** bằng một lệnh, xanh | Chạy lệnh |
| 2 | `pnpm test:all` chạy **cả 4 tầng**, xanh | Chạy lệnh |
| 3 | Mỗi tầng vẫn chạy riêng được: `test:sql`, `test:api`, `test:unit`, `test:e2e` | Chạy 4 lệnh |
| 4 | `pnpm test` **không** gọi `pnpm build` — tránh giết dev server (luật C12) | Đọc script |
| 5 | `api-contracts.ts` khai type cho **cả 21 route** | Đếm |
| 6 | **BE sửa hợp đồng → FE typecheck đỏ ngay**: đổi thử 1 field rồi chạy `pnpm typecheck` | Ảnh chụp output |
| 7 | Cổng CI chạy `pnpm test` trên mỗi PR | Đọc config |
| 8 | **Mỗi tầng có ≥1 negative test** — đếm và ghi số vào mục 8 | Bảng số liệu |
| 9 | **Không case nào trùng 2 tầng** — đối chiếu bảng phân bổ TEST-STRATEGY §2 | `ndh-sa` review, ghi kết luận |
| 10 | `e2e-out/`, `playwright-report/`, `coverage/` đã trong `.gitignore` | `git check-ignore` |
| 11 | TEST-STRATEGY §6 cập nhật **số liệu thật**, không phải số dự kiến | Đối chiếu |
| 12 | Tài liệu ranh giới BE/FE ghi rõ: ai sở hữu gì, bàn giao gì, phân xử thế nào | Đọc TEST-STRATEGY §3 |

## 7. Rủi ro

| # | Rủi ro | Cách chặn |
|---|---|---|
| 1 | `pnpm test` cần Docker → xanh ở máy dev, đỏ ở CI | CI dùng service container Postgres, hoặc Supabase branch (`M24`) |
| 2 | Suite chậm dần, người ta bắt đầu skip | Đặt trần: `pnpm test` xong dưới 2 phút. Vượt thì tách `test:quick` |
| 3 | Có case trùng 2 tầng mà không ai phát hiện | AC-9: `ndh-sa` đối chiếu bảng phân bổ, ghi kết luận |
