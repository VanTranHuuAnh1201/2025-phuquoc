## 1. Bối cảnh

Chị muốn *"tự đăng bài, chỉnh sửa nội dung"*. Thiếu nút Xem trước thì mỗi lần sửa
là một lần đoán: chị lưu → mở trang công khai → thấy sai → sửa lại → lưu lại. Mà
giữa các lần đó **khách đang xem bản sai**.

Xem trước biến vòng lặp đó thành: sửa → xem → hài lòng → mới đăng.

## 2. Phạm vi

**Trong:** nút "Xem trước" ở mọi form nội dung · render nội dung nháp trên **đúng
theme H3** (không phải khung admin) · xem được cả desktop và mobile · link chia sẻ
tạm cho người khác xem.

**Ngoài:** xem trước trên cả 4 theme (H3 là theme giao khách; các theme khác chỉ
là mẫu chọn) — ghi rõ trong ticket để không hiểu là thiếu.

## 3. Dữ liệu vào / ra

```
apps/2026-thenamduhill/src/app/admin/_shared/PreviewButton.tsx    MỚI
apps/2026-thenamduhill/src/app/preview/[token]/page.tsx           MỚI
apps/2026-thenamduhill/src/app/api/admin/preview/route.ts         MỚI — tạo token nháp
```

Cơ chế: form gửi nội dung nháp → server lưu tạm + trả token có hạn → mở
`/preview/{token}` render bằng theme H3 với dữ liệu nháp.

⚠️ Token phải **có hạn** và **không đoán được**. Route `/preview/**` phải bị chặn
trong `robots.ts` — nội dung nháp lọt vào Google là tệ hơn không có xem trước.

## 4. Luồng UI

```
Trong form CMS:
  [Lưu nháp]  [👁 Xem trước]  [Đăng]
                    │
                    ├→ mở tab mới /preview/{token}
                    │     ├ thanh trên: "Bản xem trước · chưa đăng"
                    │     ├ [Desktop] [Mobile]  ← đổi viewport ngay trong trang
                    │     └ [Sao chép link chia sẻ]  (hết hạn sau 24h)
                    └→ nội dung render bằng THEME H3, không phải khung admin
```

## 5. Tiêu chí chấp nhận (AC)

| # | AC | Kiểm bằng |
|:--:|---|---|
| 1 | Nút "Xem trước" có ở form: blog, mô tả hạng phòng, nội dung trang chủ | Đếm form |
| 2 | Xem trước render bằng **theme H3 thật**, không phải khung admin | So sánh với trang công khai |
| 3 | Nội dung nháp **chưa đăng** hiện đúng trong xem trước | Sửa không lưu → xem trước thấy bản sửa |
| 4 | Thanh trên nói rõ **"Bản xem trước · chưa đăng"** — không lẫn với trang thật | Xem UI |
| 5 | Đổi Desktop/Mobile ngay trong trang xem trước | Bấm đổi |
| 6 | Link chia sẻ tạm, **hết hạn sau 24h** | Đợi/giả lập hết hạn → 404 hoặc thông báo hết hạn |
| 7 | **Negative — bảo mật**: token sai/hết hạn → thông báo rõ bằng chữ, **không lộ nội dung** | 2 case |
| 8 | **Negative — bảo mật**: token **không đoán được** (≥128 bit ngẫu nhiên), không phải id tăng dần | Đọc code |
| 9 | **`robots.ts` chặn `/preview/**`** — nội dung nháp không được Google index | Mở `/robots.txt` |
| 10 | Trang xem trước có `<meta name="robots" content="noindex,nofollow">` — chặn hai lớp | Xem source |
| 11 | **Negative**: tạo token không có quyền `content.edit` → **403** | 1 case |
| 12 | Nội dung nháp lưu tạm **tự dọn** sau khi hết hạn — không phình DB | Đọc cron/TTL |
| 13 | Đủ 7 trạng thái UI cho nút Xem trước (luật FE1) | Kiểm |
| 14 | Song ngữ, kể cả thanh "Bản xem trước" và thông báo hết hạn | Đổi locale |
| 15 | `pnpm test` xanh, lint/typecheck sạch, `build:safe` xanh 4 theme | Chạy lệnh |

## 6. Kỹ thuật — *`ndh-sa` điền*

> ⬜ Cần chốt: lưu nháp ở bảng riêng (`content_drafts`) hay dùng Next Draft Mode
> (`draftMode()`)? Draft Mode gọn nhưng khó chia sẻ link cho người thứ ba (AC-6).
> Đổi viewport bằng `<iframe>` có width cố định hay mở cửa sổ mới?

## 7. Rủi ro

| # | Rủi ro | Cách chặn |
|---|---|---|
| 1 | **Nội dung nháp bị Google index** → duplicate content với bản đã đăng, tự hại SEO | AC-9 + AC-10: chặn hai lớp (robots.txt **và** meta noindex) |
| 2 | Token đoán được → người lạ đọc nội dung chưa đăng | AC-8: ≥128 bit ngẫu nhiên, không id tăng dần |
| 3 | Nháp phình DB, không ai dọn | AC-12: TTL + dọn tự động |
| 4 | Xem trước dùng khung admin cho nhanh → chị vẫn phải đoán | AC-2: phải là theme H3 thật. Nếu không thì ticket này vô nghĩa |
