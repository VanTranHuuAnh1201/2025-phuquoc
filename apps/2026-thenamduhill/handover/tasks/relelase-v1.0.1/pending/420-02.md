## 1. Bối cảnh

Theo quyết định **Đ3**: chỉ dựng lớp, chưa nối nhà cung cấp nào.

Mục tiêu duy nhất của ticket: khi chị chốt Ezcloud (hoặc Hotellink/Kigo), việc
cắm vào là **viết một file adapter mới** — không sửa outbox, không sửa RPC, không
sửa CMS. Đó là ý nghĩa của "thiết kế để sau này tích hợp dễ dàng".

## 2. Phạm vi

**Trong:** interface `ChannelAdapter` · implementation `noop` (ghi log, không gửi)
· worker gửi event từ outbox có retry + exponential backoff · phân biệt lỗi tạm
thời và lỗi vĩnh viễn.

**Ngoài:** adapter thật của nhà cung cấp cụ thể (chờ `M26`) · màn hình CMS → `420-03`.

## 3. Dữ liệu vào / ra

```
packages/domain-hotel/src/integration/
  channel-adapter.ts     MỚI — interface ChannelAdapter
  adapters/noop.ts       MỚI — ghi console, luôn trả thành công
  registry.ts            MỚI — đăng ký adapter theo tên, đọc từ env

apps/2026-thenamduhill/src/app/api/cron/outbox-dispatch/route.ts   MỚI
```

Interface tối thiểu — phải chịu được cả 3 mô hình đồng bộ (push webhook / pull
polling / ARI), vì chưa biết nhà cung cấp nào:

```ts
export interface ChannelAdapter {
    readonly name: string
    /** Đẩy một event ra kênh ngoài. Throw để worker retry. */
    push(event: OutboxEvent): Promise<PushResult>
    /** Lỗi này có đáng retry không — 5xx/timeout: có; 4xx sai dữ liệu: không. */
    isRetryable(error: unknown): boolean
}
```

| 1 | Interface `ChannelAdapter` đặt ở `packages/domain-hotel` — **không** ở tầng nền (luật R15) | Đọc đường dẫn |
| 2 | Adapter `noop` chạy được: cron quét outbox → event chuyển `pending` → `sent` | Chạy cron, xem DB |
| 3 | **Thêm adapter mới KHÔNG cần sửa file nào ngoài `registry.ts`** — chứng minh bằng cách thêm 1 adapter giả `echo` | `git diff` chỉ có 2 file: adapter mới + 1 dòng registry |
| 4 | Retry có **exponential backoff**: lần 1 sau 1 phút, lần 2 sau 5, lần 3 sau 25… | Đọc code + 1 case tầng 2 |
| 5 | Sau N lần thất bại → `status = 'dead'`, **không retry vô hạn** | 1 case negative |
| 6 | **Phân biệt lỗi tạm thời và vĩnh viễn**: 5xx/timeout → retry; 4xx sai dữ liệu → `dead` ngay, không retry | 2 case negative |
| 7 | `last_error` ghi **nguyên văn lỗi**, không nuốt (luật C3) | 1 case: ép lỗi → đọc `last_error` |
| 8 | **Negative**: adapter throw → outbox ghi `failed` + `attempts += 1`, **cron không chết** | 1 case |
| 9 | Cron **idempotent**: chạy 2 lần liền không gửi trùng event đã `sent` | 1 case |
| 10 | Cron có bảo vệ — chỉ gọi được bằng `CRON_SECRET` (như 2 cron sẵn có) | 1 case negative: gọi không secret → 401 |
| 11 | Env `CHANNEL_ADAPTER` chưa cấu hình → mặc định `noop`, **không crash** | 1 case |
| 12 | Không tự viết mã ký/HMAC — dùng thư viện đã kiểm chứng (luật BE12) | Đọc code |
| 13 | ≥10 case tầng 2, ≥5 negative | Đếm |
| 14 | `pnpm test` xanh, lint/typecheck sạch, 0 `any` | Chạy lệnh |
