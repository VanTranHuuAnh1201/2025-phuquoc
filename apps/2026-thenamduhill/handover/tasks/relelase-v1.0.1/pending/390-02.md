## 1. Bối cảnh

`390-01` đã có API. Ticket này làm cho CMS **thật sự dùng** nó.

Bốn màn đang đọc/ghi `catalog.store` có `persist(localStorage)` — dữ liệu chị
nhập chỉ nằm trên máy đang dùng.

⚠️ **Việc nhạy cảm nhất của ticket**: chị có thể **đã nhập dữ liệu thật** vào
CMS trên máy của mình. Chuyển sang API mà không di trú là **xoá công của chị**.
Xem AC-2.

## 2. Phạm vi

**Trong:** 4 màn CMS gọi API thật · di trú dữ liệu đang có trong localStorage ·
bỏ `persist` của `catalog.store`.

**Ngoài:** viết API → `390-01` [BE].

## 3. Dữ liệu vào / ra

```
apps/2026-thenamduhill/src/app/admin/settings/rooms/page.tsx        → /api/admin/room-types
apps/2026-thenamduhill/src/app/admin/settings/rate-plans/page.tsx   → /api/admin/rate-plans
apps/2026-thenamduhill/src/app/admin/settings/addons/page.tsx       → /api/admin/addons
apps/2026-thenamduhill/src/app/admin/settings/general/page.tsx      → /api/admin/settings/bank
apps/2026-thenamduhill/src/stores/catalog.store.ts                  bỏ persist, chỉ giữ cache phiên
```

## 4. Luồng UI

Không đổi bố cục. Chỉ đổi **nguồn dữ liệu**, thêm trạng thái `loading`/`error`
mà store cục bộ trước đây không cần.

Thêm một bước di trú, chạy **một lần**:

```
┌────────────────────────────────────────────────────────┐
│  ⚠ Phát hiện dữ liệu lưu trên máy này                  │
│                                                        │
│  5 hạng phòng · 3 gói giá đang lưu cục bộ, chưa được   │
│  đồng bộ lên máy chủ.                                  │
│                                                        │
│  [Tải lên máy chủ]   [Tải file sao lưu]   [Bỏ qua]    │
└────────────────────────────────────────────────────────┘
```
