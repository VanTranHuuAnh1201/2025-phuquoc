## 1. Bối cảnh

Mô hình contract-first do chủ dự án chốt: **FE không cần route chạy được, FE cần
biết hình dạng dữ liệu.** Tách hai thứ đó ra thì lượt 3 (FE code) và lượt 4 (BE
viết thân hàm) chạy song song thật.

Ticket này là **điểm đồng bộ duy nhất** của cả release. Làm sai ở đây thì cả hai
bên code sai — nên nó có cổng review riêng (`380-02`).

## 2. Phạm vi

**Trong:** khai interface Request/Response/Error cho mọi API mà release chạm tới.

**Ngoài — tuyệt đối không làm:**
- ❌ Viết thân hàm route
- ❌ Viết migration
- ❌ Sửa code FE

⚠️ **Viết một dòng thân hàm là FAIL ticket.** Không phải vì hình thức — mà vì
lượt 1 phải nhẹ để hai bên không chờ lâu (rủi ro RS4 ở RUNBOOK §8).

### Mỗi endpoint khai đủ 4 thứ

```ts
/**
 * POST /api/admin/room-types — tạo hạng phòng mới.
 * Quyền: price.edit (lễ tân KHÔNG có)
 */
export interface CreateRoomTypeRequest {
    name: I18nText              // BẮT BUỘC cả vi + en (luật R6)
    basePrice: number           // VNĐ nguyên, không thập phân (luật C6)
    capacity: { adults: number; children: number }
}

export interface CreateRoomTypeResponse {
    id: string                  // UUID — KHÔNG phải slug (bẫy đã gặp ở M6)
    createdAt: string           // ISO 8601, không phải Date object
}

/** Mã lỗi FE phải xử lý riêng — kèm HTTP code */
export type CreateRoomTypeError =
    | { code: 'VALIDATION_FAILED'; message: I18nText }   // 400
    | { code: 'UNAUTHORIZED';      message: I18nText }   // 401 → FE về /login
    | { code: 'FORBIDDEN';         message: I18nText }   // 403 → FE báo thiếu quyền
    | { code: 'DUPLICATE_NAME';    message: I18nText }   // 409
```

### 9.2 — `information_schema` đã đối chiếu

Đọc `information_schema.columns` + `pg_constraint` (contype='c') cho:
`room_types` · `rate_plans` · `addons` · `bookings` · `payments` · `room_units` ·
`property_settings` · `promotions` · `inventory` · `accounts` · `activity_logs`.

**Ba phát hiện làm đổi hợp đồng so với dự kiến ban đầu:**

| # | Phát hiện | Ảnh hưởng lên hợp đồng |
|:--:|---|---|
| 1 | `room_types.id`, `rate_plans.id`, `addons.id` là **`text` slug** (`chk_*_id_slug` = `^[a-z0-9][a-z0-9-]{1,62}$`), **KHÔNG phải UUID** | Ticket §3 ví dụ ghi `id: string // UUID` cho `CreateRoomTypeResponse`. **Đã khai theo DB**: slug, có ghi rõ regex. Chỉ `bookings.id`/`room_units.id`/`accounts.id` mới là UUID |
| 2 | **Không có bảng `settings`.** Cấu hình cơ sở nằm ở `property_settings`, mà bảng đó **không có cột `bank`** | `GetBankSettingsResponse` khai mọi trường **tuỳ chọn** để FE chịu được rỗng. `390-01` phải kèm migration — xem `M30` |
| 3 | `room_types` **không có cột `deleted_at`** | DELETE khai là **soft delete qua `active=false`**, không phải cột timestamp riêng |

**Enum đã đối chiếu CHECK constraint thật (không suy đoán):**

```
payments.method    bank-transfer | card | at-property | momo     ← GẠCH NGANG ✅
payments.kind      deposit | balance | refund | surcharge
bookings.status    pending_payment | confirmed | checked_in | checked_out
                   | cancelled | no_show | expired
bookings.channel   web | phone | walk-in | ota
room_units.status  available | occupied | dirty | cleaning | maintenance
room_types.group   couple | family | suite  (nullable)
activity_logs.action  created | status-changed | payment-recorded | checked-in
                      | checked-out | note-added | room-assigned
                      | price-adjusted | cancelled
```

**Ràng buộc chéo đã đưa vào hợp đồng thành mã lỗi riêng:**

- `chk_rate_plans_refund` — `refundable=false` **bắt buộc** `cancellation_rules = '[]'`
  ⇒ mã `REFUND_RULES_CONFLICT` (400)
- `chk_room_types_capacity` — `max_guests >= guests AND guests > 0` ⇒ `VALIDATION_FAILED`
- `chk_bookings_money` — `discount_total <= subtotal` **và** `total = subtotal - discount`
- `i18n_text_check` (domain) — jsonb phải có **cả `vi` và `en`, cả hai khác rỗng**
  ⇒ đây là lý do mọi `name`/`description` khai `I18nText`, thiếu là 400 chứ không
  phải lỗi 500 từ DB
